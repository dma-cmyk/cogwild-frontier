# 画像生成アートのパイプライン

参考画像（`docs/reference/visual_reference.png`）の「描き込まれたドット絵風アイソメトリック」に寄せるため、キャラチップ・肖像・建物・木や岩・地面・アイテムアイコン・タイトル画像を画像生成で作り、ゲームで使える形に加工している。
ゲームは 3D のまま（地形の起伏・影・昼夜はそのまま）で、描いた絵をカメラ正対のカード（ビルボード）として置く。カメラはピッチ −30°を保って90°刻みで4方向に回転する。建物の前面カードは45°方向／315°方向、反対面カードは135°方向／225°方向に使い、135°／315°だけは従来どおり水平反転する。反対面テクスチャは建物が画面内でカメラに背を向けた時にだけ読み込む。奥行きシェーダーは各方向のカメラ基底から再計算する。

## 流れ

1. **プロンプト定義**: `tools/art/make_prompts.py` → `art_src/prompts.json`
   - 1 行 = 1 回の生成リクエスト（`id`, `kind`, 画像ツールへ渡す `args`）。
   - 画風・背景（マゼンタ単色）・構図・グリッドの指定は共通の定数から組み立てる。
2. **生成**: OMP の `generate_image` に `args` を渡す。従来のプロンプトは `openai-codex/gpt-image-1`、アンドロイドは `openai-codex/gpt-image-2` を指定する。アンドロイドの今回の生成結果は実モデル `gpt-image-2-codex`。`prompts.json` の `input.path` は Git 共有可能なリポジトリ相対パスなので、ツール呼び出しではプロジェクトルートを基準に絶対パスへ解決する。
   - 結果は `art_src/raw/<id>.webp` に置く。容量が大きいので Git には入れない（`.gitignore`）。
   - 肖像は対応するキャラチップ画像を入力画像にして「同じ人物のバストアップ」を描かせる。v2/v3 チップは v1 を画風・縮尺の参照画像にする。
3. **加工**: `tools/art/process.py`（numpy / Pillow / scipy）。
   ```
   python3 -m venv --system-site-packages /tmp/artenv && /tmp/artenv/bin/pip install scipy
   /tmp/artenv/bin/python tools/art/process.py all          # chips|portraits|props|textures|buildings|icons|keyart
   /tmp/artenv/bin/python tools/art/process.py buildings --only b_house
   ```
   - 背景除去: アルファ付きならアルファ、なければマゼンタのクロマキーと縁の色かぶり除去。
   - グリッド検出: 連結成分の重心を行・列に割り当て、はみ出した小片（剣・弓など）も同じマスに含める。
   - 正規化:
     - キャラチップ: 立ち絵の高さを揃え、足元（浮遊機械は中心）を基準に 128×128 のマスへ。
     - 小物: 根元を中央に寄せて 1 枚のアトラスへ。
     - 地面テクスチャ: 半分ずらした自分自身と分散保存ブレンドして継ぎ目を消す。
   - 出力: `game/assets/{sprites,portraits,textures,ui}/` と、メタデータ `game/data/art/*.json`（DB テーブル `art/sprites` `art/portraits` `art/props` `art/buildings` `art/terrain` `art/icons`）。
   - Godot の取り込み設定（`.import`）も書く。
    - Web は最初の core pack に UI・フォント・地形・小物・全17種族の基本キャラチップと肖像・プレイヤー建物の正面を含める。追加の見た目 v4/v5・建物の裏側・村/盗賊/機械/拠点の絵は filename pattern で別パックに分け、ゲーム開始後に読み込む（分類の正は `tools/web/pack_split.py`、書き出しフィルタは `game/export_presets.cfg`）。新しい種族を足しても基本キャラ絵は先に表示される。キャラチップと肖像は WebP・ミップマップなし、肖像原本は 128 px。建物は Basis UASTC・ミップマップ付き・最大 768 px（glow mask は 256 px・ミップマップなし）。その他の世界の絵は Basis UASTC（ミップマップ付き、RDO quality_loss 1.5）。UI の絵は可逆・ミップマップなし。ただしタイトル画像 `assets/ui/title_keyart.jpg` は WebP 品質 0.9（元の JPEG はそのまま）。
    - `WebExtraPack` はゲーム開始後に追加パックを `user://`（Web の IndexedDB）へ保存して `ProjectSettings.load_resource_pack` で取り込み、テクスチャを使う表示を更新する。PWA service worker も追加パックを初回取得時にキャッシュし、PWA 更新で cache version を切り替える。パック未取得でも全種族の基本キャラ絵は使える。追加の見た目・建物の裏側・拠点の絵には基本表示の代替を使う。ネイティブ版では分割しない。
    - チップ/肖像の Basis 化は Core の転送量を増やすため避け、ミップマップなしと glow mask 縮小で GPU メモリを抑える。今回の Web 書き出しは core 47.85 MB、追加パック 33.13 MB（いずれも gzip 換算）。
     - 地面: 8 層の Texture2DArray。
   - 手で測った点（風車の軸、煙突、係留の高さ）は `tools/art/overrides.json` に書き、加工時に合流させる。
4. **取り込み**: `cd game && godot --headless --path . --import`

## ゲーム側での使い方（`src/visual/sprite_library.gd` ほか）

| 対象 | 仕組み |
|---|---|
| 人物・機械 | `SpriteUnitVisual`。<br>• 通常のキャラは列がコマ（一歩・立ち・一歩）、行が画面上の向き（下・左・右・上）。飛行船は1列なので立ち・歩き・行動時も列0を使い、絵が消えないようにする。行はカメラに対する向きから選び、ちらつき防止の余裕を持たせる。<br>• 攻撃・被弾は、踏み込み／のけぞり・インスタンスシェーダーのフラッシュ・弾道や衝撃エフェクト・浮動ダメージ表示で伝える。死亡はフラッシュ後に横倒しになり、死亡エフェクトが出る。<br>• 作業・レベルアップはカードの小さな動き（工具動作・跳ねる）で表す。運搬物は描いた資源アイコンで表示する。 |
| 見た目の選び方 | 種族 × 見た目 5 種（作業・戦士・射手・技師・学者）× 性別。<br>追加13種族は各組み合わせ v1〜v3 の3枚（worker はさらに v4 で4枚）、初期4種族は4枚（人間・スタウトキン・ヴァルピンの worker は5枚）を登録する。Web の core pack は全種族の基本の絵を含み、初期4種族の v4/v5 と追加13種族の v3/v4 は追加パックに入る。DNA に `art_variant`（0 始まり、創設者は作成画面の「Look 1/n」で設定）があればそれでチップと肖像の両方を選び、なければ DNA hash による決定論的選択をする（村人・町の人＝`faction_style` が neutral / merchant は全枚数から。旧セーブのプレイヤー側は互換のため v1/v2 から）。新たにプレイヤー居住者へ加わる人物は同じ種族・装備由来の見た目・性別の生存居住者数を数え、最少の variant を割り当てる。同数なら DNA hash による順序で決める（乱数を消費しない）。`SpriteLibrary.variant_count(dna)` は読み込み可能な枚数を返す。見た目の種類は装備から決まり、装備変更時も同じ variant を保つ。アンドロイドの作業姿は帽子や全身服で機械の頭・装甲を隠さず、工具ベルトと青い布を添える。盗賊・機械・飛行船は専用の絵を使う。使われなくなったチップ・肖像のテクスチャは 5 秒ごとの掃除で解放する。 |
| 会社の色 | 絵の青い布・旗だけを色相回転して会社の色に合わせる（シェーダー）。 |
| 肖像 | 生成したバストアップ（人物）、チップの正面立ち絵（機械）。 |
| 建物 | 前面と反対面の絵をカメラ方向に応じて切り替え、反対面のテクスチャは必要になるまで遅延読込する。切替はカメラ回転完了と画面進入の通知で行い、非アニメーション建物に毎フレーム処理を持たせない。カードの各画素に「建物の手前 2 面の壁の上にある」とした奥行きを書き込むので、ユニットが建物の前・横・裏を歩いても正しく隠れる。正面のない対称的な建物には `back_symmetric` を付ける。<br>• 影: 元の 3D 形状を影専用に残しているので、影の形は建物に合う。<br>• 建設中: 下から絵を出し、手前に足場の絵を重ねる。<br>• 夜: 暖色の窓・灯りを自動抽出したマスクで光らせる。<br>• 風車: 羽根を別カードにして回す。 |
| 木・岩・草花 | チャンク単位の MultiMesh（1 種類の揺れごとに 1 回の描画）。影はカードを太陽に向けて落とす。 |
| 地面 | 8 層のテクスチャを頂点ごとの重みで混ぜる。境界はテクスチャの明るさで崩して手描き風にする。急斜面は岩（三方向投影）。 |
| アイテムアイコン | 品質色の枠の中に描いたアイコンを合成する（`Icons.item_icon`）。 |
| タイトル画面 | 生成したキーアート（`assets/ui/title_keyart.jpg`）。 |

絵がないもの（石壁・柵、未対応の機械の型など）は、従来の手続き生成ローポリに自動で戻る。
`SpriteLibrary.enabled = false` にすると全体を旧表示で確認できる。

## 追加・差し替えの手順

- **新しい見た目や建物**:
  1. `make_prompts.py` に項目を足して `art_src/prompts.json` を再生成する。人物の 2 枚目以降は `chip_<race>_<look>_v2` 〜 `_v5` と対応する肖像。v2 以降のチップは v1 をスタイル・縮尺参照として渡し、青い会社色の布アクセントだけを青として維持する。v3 以降は各 race × look ごとに異なる男女の外見にする。
  2. 生成画像を `art_src/raw/<id>.webp` に置き、`process.py` の `CHIP_SHEETS` / 肖像対応表へ追加する。処理後の art ID は `race_look_gender@v2` 〜 `@v5`、画像名は `_v2.png` 〜 `_v5.png`。チップの後に肖像を生成し、両性別のチップと肖像をそろえる。`process.py` は `chips` / `portraits` など対象を指定して実行し、既存の `.import` の uid を保つ（`all` は建物の取り込み設定も書き直すので使わない）。
  3. `process.py` で加工し、各 PNG の `.import` 設定は対応する v2 画像と同じにする。Web preset 適用後 Godot で `--import` し、背景透過・4方向・3コマ・縮尺・両性別の差をコンタクトシートで確認する。
- **品質確認**: 加工結果を並べた一覧画像を必ず目で見る（グリッドのずれ・切れ・背景の残り・向きの取り違え）。
  - `tests/test_painted_art.gd` は次を検査する。
    - ゲームが作り得る全ユニット・建物・小物に絵がある。
    - メタデータが指すテクスチャが読める。
    - 装備によって見た目が切り替わる。
    - 全17種族の見た目・性別ごとに読込可能なチップと肖像が揃い、旧セーブのプレイヤー側の v1/v2 選択と居住者の least-used 割当が維持され、村人・町の人は全枚数から選ばれる。
    - 会社の色の回転が正しい。

### 神話の種族・4 つ目の見た目・村の建物（その 5）

- `make_prompts.py` の `NEW_RACES` / `NEW_RACES_V2`（ミノタウロス・ケンタウロス・ハーピー・ラミア・鬼・天狗、各 5 見た目 × 男女 × v1/v2）、`NONWORKER_V4_APPEARANCE`（既存 4 種族の戦士・射手・技師・学者の v4）、`VILLAGE_BUILDINGS`（10 種族の村の家 3×3 と集会所 5×5、集会所の裏側）。
  - 新種族の v1 は人間の同じ見た目の v1 を、v2 は自分の v1 を画風・縮尺の参照に渡す。体の違いは `NEW_RACE_BODY`（馬の下半身・蛇の尾・翼の腕など）と `NEW_RACE_FRAMES`（ケンタウロスは速歩、ラミアは這う動き）で指示する。
  - 村の色は青を避ける（青はプレイヤーの会社の色として色相回転するため）。
- 182 枚のうち 173 枚は `openai-codex/gpt-image-1`。利用上限に達した間に、集会所の裏側 9 枚を `google-antigravity/gemini-3-pro-image`（入力を PNG にし、`image_size` を外す）で作り、1536×1024 / 1024×1024 に縮尺を合わせた。残り（鬼と天狗の肖像、既存 4 種族の v4 の肖像、天狗の集会所の裏側）は上限の回復後に gpt-image-1 で作った。`art_src/raw/_log.txt` に生成元を記録している。
- 肖像がない見た目はチップの正面コマを肖像として使い（機械と同じ）、裏側がない建物は正面の絵を使う。raw を `art_src/raw/<id>.webp` に置いて `process.py portraits --only <id,...>` / `process.py buildings --only <id>` を実行すれば差し替わる（表は既存の行と合流する）。
- ケンタウロス・ラミアなど体の大きい種族は `SpriteLibrary.RACE_HEIGHT` で絵の高さを変える。作成画面のプレビューもこの高さに合わせて写す。

### ローグライク定番の種族・町の建物（その 6）

- `make_prompts.py` の `CLASSIC_RACES` / `CLASSIC_RACES_V2` / `CLASSIC_RACE_BODY`（ゴブリン・オーク・コボルト・リザードマン・ノーム・ハーフリング）を `NEW_RACES` 系の表に合流させ、神話の種族と同じ手順（v1 は人間の同じ見た目、v2 は自分の v1 を参照）で 5 見た目 × 男女 × v1/v2 のチップと肖像を作る。`VILLAGE_BUILDINGS` にこの 6 種族の家と集会所、`TOWN_BUILDINGS` に町のギルド会館 5×5・酒場・雑貨屋・鍛冶屋・宿屋 4×4・噴水 3×3（噴水以外は裏側も）を足した。
- `process.py` は `NEW_RACES` に 6 種族、`TOWN_BUILDINGS` で `b_t_<id>` → 建物の見た目 `t_<id>@0` と足元の大きさを持つ。噴水は `back_symmetric`。
- 152 枚すべて `openai-codex/gpt-image-1`（新規 149 枚と、頭が切れた肖像 3 枚の作り直し）。途中で利用上限に達し、ノームとハーフリングの肖像など 21 枚は上限の回復後に作った。作り直した 3 枚は構図に「帽子とあごまで全体を入れる」を足している（元の raw は `build/r6spec/rejected/`）。
- ブラウザ版では `tools/web/pack_split.py` の `LATE_RACES` に 6 種族、`SITE_BUILDINGS` に町（`t_*`）を足し、追加パックに入れている。

### 追加13種族の v3/v4（まとめ生成）

- 村の住民の半数は作業着なので、追加13種族の作業着に v3/v4 を、ほかの 4 見た目に v3 を足した（作業着は `NEW_RACES_V3` / `NEW_RACES_V4`、ほかは `EXTRA_LOOK_STEMS` / `EXTRA_LOOK_DETAILS`。服は作業着が `EXTRA_WORKER_OUTFIT`、ほかが既存 4 種族の 4 つ目の服 `V4_LOOKS`、アンドロイドは `ANDROID_WORKER_OUTFIT` / `ANDROID_LOOK_OUTFIT`）。画像生成の上限を節約するため、1 リクエストに詰める。
  - チップ（`kind: chip_batch`）: 1 枚に男女 4 人（12 列 × 4 行）。作業着は 1 種族の v3 と v4、ほかは 1 種族の 2 見た目の v3。参照画像は種族の v1 チップ。
  - 肖像（`kind: portrait_batch`）: 1 枚に 3 シート分（男女 6 人、3 列 × 2 行）。参照画像はそのチップ 3 枚。
  - 結果は `art_src/raw/<batch id>.webp` に置き、`python3 tools/art/split_batches.py` でシート別の raw（`chip_<種族>_worker_v3` など）に切ってから `process.py chips|portraits --only ...` を実行する。
  - 詰めると隣の絵が接して 1 つの塊になる。`process.py` は 24 体に満たないとき、幅・高さが 1.5 倍を超える塊を最も細い列・行で切り離す。それでも格子が崩れた回は作り直した。
- 使った回数: 作業着はチップ 13・肖像 9・作り直し 2 の計 24 回、ほかの見た目はチップ 26・作り直し 3・肖像 8 の計 37 回（1 リクエスト 1 シートの従来方式では合わせて 149 回）。
- 肖像の残り 5 回分（`batch_portrait_looks_14`〜`18`）は、OMP の画像生成が利用上限に達したため、同じプロンプトと参照チップ画像を ChatGPT の画面に直接渡して作った。結果は `art_src/raw/batch_portrait_looks_14〜17.png` に置いて `split_batches.py` で切り、18（アンドロイドの学者 1 シート、男女 2 人）は切り分けずに `art_src/raw/portrait_android_scholar_v3.png` として `process.py portraits` へ渡した。帽子や触角の先端が上端でわずかに切れる絵があるので、背の高い帽子・冠の種族は「頭の上に余白を多く取る」を添えると切れにくい。

### ダンジョン入口・主・巨獣

- `chip_giants` は6列×4行の1枚に「地下庫の主」と「苔背の巨獣」を各3コマ×4方向で生成した。`process.py` の `CHIP_SHEETS` で2つのシートに分け、`assets/sprites/chars/dungeon_master.png` / `wild_colossus.png` を登録する。通常の機械より大きい実寸は `SpriteLibrary.MACHINE_HEIGHT` とユニットのDNAのscaleで決める。
- 入口は `b_dungeon_gate` の単体画像。`process.py buildings --only b_dungeon_gate` で背景除去・足元3×3に合わせ、通常画像と glow mask を生成する。実行中に増えた入口も `WorldView` がこの建物を作る。
- 使用モデルは gpt-image-2（ツール出力では gpt-image-2-codex）。raw は `art_src/raw/chip_giants.webp` / `b_dungeon_gate.webp`、プロンプトは `make_prompts.py` → `art_src/prompts.json` に保存する。要求と異なる画像サイズが返った回も、原寸から既存の切り出し・正規化を通す。
- 地下の壁・床は既存の画像生成した岩・石畳テクスチャを使う。階段の矢印とボスの予兆円は、方向・発見状態・残り時間を読みやすくするコード生成のしるし。
- 実画面の確認対象: 入口からの入退場、暗い地下の壁と通路、主の赤い予兆円、主と守兵の大きさの違い、野外の巨獣。画面は `docs/screenshots/dungeon_master_warning.png` など。

## 制約・注意

- 生成は毎回結果が変わる。同じプロンプトでも別の絵になるので、良い結果の raw を残しておく。
- 建物の地面の菱形はおよそ幅:高さ=2:1。正射影カメラのピッチを−30°に合わせる。カード基準点・建物奥行き・ユニット／小物ビルボードは常に現在のカメラ基底に従う。
- 全17種族の見た目・性別ごとに、追加13種族は作業着 4 種類・ほかは 3 種類、初期4種族は4〜5種類の描画済み look を用意する。`art_variant` で選び、髪や衣服の細部そのものをゲーム内シェーダーで描き換える仕組みではない。
- 生成画像はモデルの利用規約に従って使う。プロンプトと加工手順はすべてこのリポジトリにあり、API キーはコードに含めない。
