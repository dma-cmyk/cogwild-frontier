# 画像生成アートのパイプライン

参考画像（`docs/reference/visual_reference.png`）の「描き込まれたドット絵風アイソメトリック」に寄せるため、キャラチップ・肖像・建物・木や岩・地面・アイテムアイコン・タイトル画像を画像生成で作り、ゲームで使える形に加工している。
ゲームは 3D のまま（地形の起伏・影・昼夜はそのまま）で、描いた絵をカメラ正対のカード（ビルボード）として置く。カメラは絵の向き（ピッチ −30°・ヨー 45°）に固定する。

## 流れ

1. **プロンプト定義**: `tools/art/make_prompts.py` → `art_src/prompts.json`
   - 1 行 = 1 回の生成リクエスト（`id`, `kind`, 画像ツールへ渡す `args`）。
   - 画風・背景（マゼンタ単色）・構図・グリッドの指定は共通の定数から組み立てる。
2. **生成**: OMP の `generate_image`（モデル `openai-codex/gpt-image-1`）に `args` を渡す。`prompts.json` の `input.path` は Git 共有可能なリポジトリ相対パスなので、ツール呼び出しではプロジェクトルートを基準に絶対パスへ解決する。
   - 結果は `art_src/raw/<id>.webp` に置く。容量が大きいので Git には入れない（`.gitignore`）。
   - 肖像は対応するキャラチップ画像を入力画像にして「同じ人物のバストアップ」を描かせるので、チップを先に作る。v2 チップは v1 を画風・縮尺の参照画像にする。
3. **加工**: `tools/art/process.py`（numpy / Pillow / scipy）。
   ```
   python3 -m venv --system-site-packages /tmp/artenv && /tmp/artenv/bin/pip install scipy
   /tmp/artenv/bin/python tools/art/process.py all          # chips|portraits|props|textures|buildings|icons|keyart
   /tmp/artenv/bin/python tools/art/process.py buildings --only b_house
   ```
   - 背景除去: アルファ付きならアルファ、なければマゼンタのクロマキーと縁の色かぶり除去。
   - グリッド検出: 連結成分の重心を行・列に割り当て、はみ出した小片（剣・弓など）も同じマスに含める。
   - 正規化:
     - キャラチップ: 立ち絵の高さを揃え、足元（浮遊機械は中心）を基準に 128×128 のマスへ。
     - 小物: 根元を中央に寄せて 1 枚のアトラスへ。
     - 地面テクスチャ: 半分ずらした自分自身と分散保存ブレンドして継ぎ目を消す。
   - 出力: `game/assets/{sprites,portraits,textures,ui}/` と、メタデータ `game/data/art/*.json`（DB テーブル `art/sprites` `art/portraits` `art/props` `art/buildings` `art/terrain` `art/icons`）。
   - Godot の取り込み設定（`.import`）も書く。
     - ワールド用: ミップマップあり・BC7 圧縮（VRAM を約 1/4 に）。
     - UI 用: 非圧縮・ミップマップなし。
     - 地面: 8 層の Texture2DArray。
   - 手で測った点（風車の軸、煙突、係留の高さ）は `tools/art/overrides.json` に書き、加工時に合流させる。
4. **取り込み**: `cd game && godot --headless --path . --import`

## ゲーム側での使い方（`src/visual/sprite_library.gd` ほか）

| 対象 | 仕組み |
|---|---|
| 人物・機械 | `SpriteUnitVisual`。<br>• 列はコマ（一歩・立ち・一歩）、行は画面上の向き（下・左・右・上）。行はカメラに対する向きから選び、ちらつき防止の余裕を持たせる。<br>• 攻撃・被弾は、踏み込み／のけぞり・インスタンスシェーダーのフラッシュ・弾道や衝撃エフェクト・浮動ダメージ表示で伝える。死亡はフラッシュ後に横倒しになり、死亡エフェクトが出る。<br>• 作業・レベルアップはカードの小さな動き（工具動作・跳ねる）で表す。運搬物は描いた資源アイコンで表示する。 |
| 見た目の選び方 | 種族 × 見た目 5 種（作業・戦士・射手・技師・学者）× 性別。<br>各組み合わせに `race_look_gender`（v1）と `race_look_gender@v2`（PNG 名は `_v2`）を登録する。DNA に `art_variant`（0 始まり、創設者は作成画面の「見た目 1/2」で設定）があればそれでチップと肖像の両方を選び、なければ seed・髪・肌などから決定論的に選ぶ（生成時に乱数を追加で引かないので、同じシードの世界は変わらない）。`SpriteLibrary.variant_count(dna)` は読み込み可能な枚数を返す。見た目の種類は装備から決まり、装備変更時も同じ variant を保つ。盗賊・機械・飛行船は専用の絵を使う。 |
| 会社の色 | 絵の青い布・旗だけを色相回転して会社の色に合わせる（シェーダー）。 |
| 肖像 | 生成したバストアップ（人物）、チップの正面立ち絵（機械）。 |
| 建物 | カードの各画素に「建物の手前 2 面の壁の上にある」とした奥行きを書き込むので、ユニットが建物の前・横・裏を歩いても正しく隠れる。<br>• 影: 元の 3D 形状を影専用に残しているので、影の形は建物に合う。<br>• 建設中: 下から絵を出し、手前に足場の絵を重ねる。<br>• 夜: 暖色の窓・灯りを自動抽出したマスクで光らせる。<br>• 風車: 羽根を別カードにして回す。 |
| 木・岩・草花 | チャンク単位の MultiMesh（1 種類の揺れごとに 1 回の描画）。影はカードを太陽に向けて落とす。 |
| 地面 | 8 層のテクスチャを頂点ごとの重みで混ぜる。境界はテクスチャの明るさで崩して手描き風にする。急斜面は岩（三方向投影）。 |
| アイテムアイコン | 品質色の枠の中に描いたアイコンを合成する（`Icons.item_icon`）。 |
| タイトル画面 | 生成したキーアート（`assets/ui/title_keyart.jpg`）。 |

絵がないもの（石壁・柵、未対応の機械の型など）は、従来の手続き生成ローポリに自動で戻る。
`SpriteLibrary.enabled = false` にすると全体を旧表示で確認できる。

## 追加・差し替えの手順

- **新しい見た目や建物**:
  1. `make_prompts.py` に項目を足して `art_src/prompts.json` を再生成する。人物の2枚目は `chip_<race>_<look>_v2` と `portrait_<race>_<look>_v2`。v2 プロンプトは v1 チップをスタイル・縮尺参照として渡し、青い会社色の布アクセントは維持しつつ髪型・髪色・服の補色を変える。
  2. 生成画像を `art_src/raw/<id>.webp` に置き、`process.py` の `CHIP_SHEETS` / portrait 対応表へ追加する。処理後の art ID は `race_look_gender@v2`、画像名は `race_look_gender_v2.png`。両性別のチップと肖像をそろえる。
  3. `process.py` で加工し、各 PNG の `.import` 設定は対応する v1 画像と同じにする。`--import` 後に背景透過・4方向・3コマ・縮尺・両性別の差をコンタクトシートで確認する。
- **品質確認**: 加工結果を並べた一覧画像を必ず目で見る（グリッドのずれ・切れ・背景の残り・向きの取り違え）。
  - `tests/test_painted_art.gd` は次を検査する。
    - ゲームが作り得る全ユニット・建物・小物に絵がある。
    - メタデータが指すテクスチャが読める。
    - 装備によって見た目が切り替わる。
    - 40 種すべてに2つの読込可能なチップと肖像があり、DNA の明示 variant と旧セーブの決定論的選択が一致する。
    - 会社の色の回転が正しい。

## 制約・注意

- 生成は毎回結果が変わる。同じプロンプトでも別の絵になるので、良い結果の raw を残しておく。
- 建物の地面の菱形はおよそ幅:高さ=2:1。正射影カメラのピッチを−30°に合わせ、建物の奥行き・カード基準点・ユニット／小物のビルボードは共通のカメラ基底に従う。
- 40 種の種族・見た目・性別の組み合わせごとに2種類の描画済み look を用意する。`art_variant` で選び、髪や衣服の細部そのものをゲーム内シェーダーで描き換える仕組みではない。
- 生成画像はモデルの利用規約に従って使う。プロンプトと加工手順はすべてこのリポジトリにあり、API キーはコードに含めない。
